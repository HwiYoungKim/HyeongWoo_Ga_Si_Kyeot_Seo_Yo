# 선수 경매 — 라이브 팀원 경매 서버

포인트로 팀원(선수)을 입찰해 팀을 꾸리는 **실시간 경매 웹 서비스**입니다.
**개인 PC에서 `app.py` 하나로 서버를 열고** 팀장·관전자는 링크로 접속합니다. (동시 접속 약 8~20명 규모를 가정)

- 서버: Python (Flask + Flask-SocketIO) — 경매 규칙·타이머·권한 판정은 **전부 서버**가 합니다.
- 화면: 순수 JS(ES module) + CSS. 빌드 도구 없음. (디자인은 `static/css/style.css`만 바꾸면 됩니다.)
- 저장: 방마다 JSON 파일(`data/`). 서버를 껐다 켜도 진행 중인 경매가 **일시정지 상태로 복구**됩니다.

## 빠른 시작

```bash
pip install -r requirements.txt      # Python 3.10 이상
python app.py                        # 내 PC에서만 접속 (127.0.0.1:5000)
```

실행하면 콘솔에 **관리자 키**가 표시되고 브라우저가 열립니다. 키를 입력하고 방을 만드세요.

| 상황 | 명령 |
|---|---|
| 같은 와이파이/공유기의 다른 사람도 접속 | `python app.py --lan` (윈도우 방화벽 허용 창이 뜨면 "개인 네트워크" 허용) |
| 포트가 이미 사용 중 (macOS는 5000을 AirPlay가 쓰는 경우가 있음) | `python app.py --port 5055` |
| **다른 와이파이/LTE 사람도 접속 (추천)** | `python app.py --tunnel` — `cloudflared`(Cloudflare Tunnel)를 자동으로 켜고 공개 주소를 만들어 보여줍니다. 시작 후 접속 자가 점검 결과(`[확인]`/`[경고]`)가 출력됩니다. 터널은 `localhost`가 아닌 `127.0.0.1` 로 연결합니다 (윈도우에서 `localhost` 가 IPv6 로 풀려 연결이 안 되는 문제 방지) |
| 링크 주소 | 방을 만들 때 나오는 링크는 `--tunnel`/`--public-url` 주소로 자동 생성됩니다. `127.0.0.1`·`localhost` 로 만든 링크는 **다른 사람이 열 수 없어** 화면에 경고가 표시됩니다 |
| 터널을 직접 켠 경우 | `python app.py --public-url https://xxxx.trycloudflare.com --trust-proxy` (터널은 `cloudflared tunnel --url http://127.0.0.1:5000`) |
| 터널이 느리거나 자주 끊김 | `python app.py --tunnel --tunnel-protocol http2` (학교/공용 와이파이는 UDP 가 막혀 기본 방식(quic)이 느린 경우가 많습니다) |
| HTTPS 직접 사용 | `python app.py --cert cert.pem --key key.pem` |
| 관리자 키를 고정 | `python app.py --admin-key "내가정한키"` 또는 환경변수 `AUCTION_ADMIN_KEY` |

저장된 방 관리 (서버를 띄우지 않고 실행 후 종료):

```bash
python app.py --list-rooms            # 방 목록
python app.py --delete-room <방ID>    # 방 하나 삭제 (선수 정보 포함)
python app.py --purge-days 7          # 7일 넘게 안 쓴 방 전부 삭제
```

## 사용 흐름

1. **주최자**: 홈에서 방 제목·팀 수(N)·팀당 인원(M)을 정해 방을 만듭니다. → 접속 링크 3종이 **한 번만** 표시됩니다.
   - 주최자 링크(본인용) / 팀장 링크(팀마다 다름) / 관전자 공용 링크
2. 주최자 화면에서 설정(기본 포인트, 입찰 단위, 타이머, 순서 공개 여부), 팀장 이름·핸디캡, **매물(선수) 등록**을 하고 `경매 시작`.
   - 매물 수는 `N × (M − 1)`명이어야 시작됩니다. (붙여넣기로 일괄 등록 가능)
   - 선수마다 **이름 · 배틀태그 · 포지션(탱커/딜러/힐러 아이콘을 눌러 켜고 끔, 여러 개 선택 가능) · 영웅(최대 5) · Elo · 소개 · 이미지(0~2장)** 를 입력합니다.
   - 저장하면 모든 선수가 **영구 선수 명부**에도 보관되어, 방을 지워도 다음 경매에서 `이 방에 추가`로 불러올 수 있습니다.
3. **팀장**: 자기 링크로 접속해 입찰 버튼/금액 입력으로 입찰합니다.
4. 경매가 끝나면 **잔여 포인트가 많은 팀부터** 대진 상대를 지명합니다. (팀장이 없으면 주최자가 대신 지명)
5. **관전자**: 현황 열람과 채팅만 가능합니다.

주최자는 경매 중 `일시정지/재개`, `강제 낙찰`, `유찰 처리`, 참가자 `링크 재발급`, `방 영구 삭제`를 할 수 있습니다.

## 선수 프로필과 영구 명부

| 항목 | 규칙 |
|---|---|
| 배틀태그 | 선택. `이름#숫자` — 이름 3~12자(글자/숫자, 숫자로 시작 불가), 숫자 4~8자. 같은 방에서 중복 불가 |
| 포지션 | **필수.** 탱커/딜러/힐러 중 **1개 이상** (중복 선택 가능, 예: 탱커+힐러). 예전에 저장된 한 개짜리 포지션은 자동으로 옮겨집니다 |
| 영웅 | 최대 5개. `server/heroes.py` 의 목록(2026 시즌 5, 54명)에 있는 값만 허용. 새 영웅은 그 파일에 한 줄 추가 |
| 이미지 | 0~2장. 0장이면 화면에 "이미지 없음"이 표시됩니다 |

- **이미지 처리**: 올린 파일을 그대로 저장하지 않고 서버가 열어서 새 WebP로 다시 만듭니다. EXIF(위치·카메라), 숨은 데이터가 사라지고, 이미지가 아닌 파일(HTML/SVG/실행파일)은 거부됩니다. 긴 변 1600px, 업로드 6MB·36MP 상한.
- **누가 볼 수 있나**: 주최자는 전원, 팀장·관전자는 *지금 경매 중인 선수*의 프로필·이미지만 봅니다. 이미지는 토큰 헤더가 필요한 API로만 받을 수 있고, 서버가 같은 규칙으로 다시 검사합니다. (이미지 id를 알아도 권한이 없으면 404)
- **영구 보관**: `data/roster.json` + `data/images/`. 방 삭제·보존기간 정리·서버 재시작과 무관하게 남습니다. 낙찰가·소속팀은 저장하지 않고 프로필만 저장합니다.
- **지우는 법**: 화면의 `저장된 선수 명부 → 명부에서 삭제`(다른 곳에서 안 쓰는 이미지는 즉시 삭제), 또는 `python app.py --list-roster` / `--wipe-roster`. 이미지를 선수에서 빼고 저장해도 즉시 삭제됩니다. 저장 없이 버려진 업로드는 24시간 뒤 정리됩니다.
- 배틀태그·이미지는 실명은 아니지만 **개인을 특정할 수 있는 정보**입니다. 현재 매물의 배틀태그와 이미지는 팀장·관전자 링크를 가진 사람에게 보입니다. (공개 범위는 `server/views.py` 한 곳에서 바꿉니다)
- 영웅 이미지·역할 아이콘은 Blizzard 저작물이라 쓰지 않았습니다. 영웅은 이름 텍스트, 포지션 아이콘은 직접 그린 단순 SVG입니다.

## 구글 드라이브로 자동 백업 (선택)

구글 계정 연동 없이, PC에 설치된 **Google Drive for Desktop** 앱의 동기화 폴더를 백업 위치로 지정하는 방식입니다.

```bash
python app.py --backup-dir "G:\내 드라이브\경매백업"      # 예: Windows. 경로는 본인 PC의 드라이브 폴더
python app.py --backup-dir ~/GoogleDrive/auction-backup     # 예: macOS/Linux
```

- 서버가 켜져 있는 동안 10초마다(`--backup-interval`) 바뀐 파일만 그 폴더로 복사하고, 종료할 때 한 번 더 복사합니다. 그 뒤 드라이브에 올리는 일은 드라이브 앱이 합니다.
- 복사 대상은 방 데이터, 선수 명부, 이미지뿐입니다. 선수에서 이미지를 빼거나 명부에서 삭제하면 백업 쪽 파일도 지워집니다. (드라이브 휴지통에는 일정 기간 남을 수 있습니다.)
- 백업 폴더 안의 다른 파일은 건드리지 않습니다. 데이터 폴더와 겹치는 폴더는 거부합니다.
- **복구**: 백업 폴더의 `rooms/`, `images/`, `roster.json`을 새 PC의 `data/` 폴더에 그대로 복사하고 서버를 켜면 됩니다.
- 주의: 파일은 **암호화되지 않은 채** 구글 드라이브에 올라갑니다. 배틀태그·사진이 들어 있으니 폴더를 다른 사람과 공유하지 마세요. 방 파일에는 접속 링크의 해시만 있고 링크 원문은 없습니다.

## 경매 규칙

| 항목 | 동작 |
|---|---|
| 매물 순서 | 시작 시 Fisher-Yates 셔플. `PUBLIC`이면 순서(이름·포지션만) 공개, `BLIND`면 인원수만 공개 |
| 입찰 검증 (서버) | ① 경매 진행 중·일시정지 아님 ② 팀 정원에 빈자리 ③ 내가 최고 입찰자가 아님 ④ 최소 입찰 단위 이상 ⑤ 보유 포인트(−유보금) 이하 |
| 입찰 단위 | 고정 금액(+N P) 또는 비율(현재가의 N% 이상, 올림, 최소 +1) |
| 최소 입찰 | 첫 입찰 최소 금액은 **1P 이상의 정수**(기본 1P). 0P 입찰·낙찰은 불가능합니다. 0P 는 아무도 낙찰받지 못한 선수를 빈자리에 **자동 배정**할 때만 생깁니다 |
| 타이머 | 기본 시간 3–120초(기본값 **15초**). 방식 선택: **초기화(RESET, 기본)** 더 높은 입찰이 승인될 때마다 남은 시간을 기본 시간(15초)으로 되돌림 / **연장(EXTEND)** 남은 시간이 연장 시간보다 짧을 때만 연장 시간으로 회복, 연장 0초 = 순발력 모드 |
| 낙찰/유찰 | 시간 종료 시 최고 입찰자에게 낙찰(포인트 차감), 입찰 없으면 유찰 큐 뒤로 |
| 재경매 | 정규 큐 소진 후 유찰자만 다시 경매 1회. 그래도 남으면 빈자리에 **0P 무작위 자동 배정** |
| 자동 배정 | 빈자리가 있는 팀이 1팀뿐이면 남은 매물을 즉시 0P 배정 (교착 방지) |
| **포인트 소진 강제 정지** | 정규 경매·재경매 모두, 빈자리가 있는 **모든 팀장이 최소 입찰가를 낼 수 없게 되면** 경매를 멈추고 남은 선수를 0P로 자동 배정합니다. 매물이 바뀔 때마다 검사합니다 |
| 즉시 낙찰 | 입찰 직후 **나머지 팀 중 그 금액을 넘길 수 있는 팀이 없으면** 타이머를 기다리지 않고 바로 낙찰합니다 |
| 유찰자 목록 | 대기열 카드에 유찰된 선수 명단(이름·포지션)이 주최자·팀장·관전자 모두에게 표시됩니다. `재경매 대기` / `재경매 유찰` 구분 |
| 대진 | 잔여 포인트 내림차순(동률은 무작위)으로 상대 지명. 홀수 팀이면 마지막 팀 부전승 |
| 핸디캡 | 팀장별 시작 포인트 가감 |
| 유보금(선택) | 빈자리 1칸당 남겨둘 최소 포인트. 포인트를 다 써서 정원을 못 채우는 상황을 방지 |

## 동시 접속 30명 / 속도

외부 유료 서비스 없이 **이 PC 한 대로** 30명을 처리합니다. (로컬 부하 테스트: 주최자 1 + 팀장 8 + 관전자 21명 접속)

| 항목 | 최적화 전 | 최적화 후 |
|---|---|---|
| 입찰 → 30명 전원 화면 갱신 | 최대 약 50ms | 최대 약 57ms (서버 처리는 원래도 충분히 빠름) |
| 30명 동시 입장 | 0.64초 | 0.13초 |
| 방 첫 화면 (왕복 150ms 가정) | 2.25초, 요청 20건 | 1.2초, 정적 파일 압축 |
| 재방문 | 매번 20건 다시 요청 | 정적 파일은 캐시에서 바로 (약 0.75초) |
| 동시 입찰 8명 | 승인 정확히 1건 | 동일 (규칙 변화 없음) |

한 일:
- **웹소켓으로 바로 접속** (폴링→업그레이드 왕복 3~4번 제거). 웹소켓이 막힌 망에서는 자동으로 폴링으로 전환.
- **정적 파일**: 시작 시 메모리에 올려 gzip 압축, 내용 버전이 들어간 주소(`/s/<버전>/…`)로 1년 캐시, JS 모듈 전체를 `modulepreload` 로 한꺼번에 병렬 로딩.
- **디스크 저장을 입찰 경로 밖으로**: 방 락 안에서는 직렬화만 하고 `fsync` 는 별도 스레드가 0.25초 단위로 묶어 처리 (종료/Ctrl+C 시 즉시 저장). 윈도우에서 입찰이 디스크를 기다리지 않습니다.
- **입장/퇴장 알림 묶음 전송**: 30명이 동시에 들어와도 전체 상태 전송은 한두 번.
- 속도가 느리다면 먼저 `--tunnel-protocol http2` 를 써 보세요. 가장 큰 변수는 PC의 업로드 속도와 터널 구간입니다.

## 외부 주소가 안 열릴 때

| 화면/증상 | 뜻 | 해결 |
|---|---|---|
| `DNS_PROBE_FINISHED_NXDOMAIN` | 그 주소가 **존재하지 않음**. 터널이 꺼졌거나, 서버를 다시 켜서 **주소가 바뀜** (빠른 터널 주소는 켤 때마다 새로 만들어집니다) | 서버를 다시 켜고 이번에 출력된 **새 주소**를 쓰세요. 이미 나눠 준 링크는 `https://○○○.trycloudflare.com` 부분만 새 주소로 바꾸면 `/r/…#t=…` 뒤쪽은 그대로 씁니다 |
| 이 PC 에서만 안 열림 | 이 PC/망의 DNS 문제 | DNS 를 1.1.1.1 / 8.8.8.8 로 변경, `ipconfig /flushdns` |
| 502 / 1033 / 530 | 터널은 있으나 서버가 꺼졌거나 터널이 끊김 | `app.py` 창 확인, 서버 재시작 |
| 429 | 터널 동시 처리 한도(200건) 초과 | 잠시 후 재시도 |

- 서버를 `--tunnel` 로 켜면 cloudflared 가 **Cloudflare 에 실제로 연결됐는지**까지 확인합니다. 기본 방식(quic)이 안 붙으면 자동으로 http2 로 다시 시도하고, 그래도 안 되면 cloudflared 의 마지막 로그와 해결 순서를 보여 줍니다. (주소는 발급됐는데 연결이 안 된 상태가 바로 브라우저의 `NXDOMAIN` / `getaddrinfo failed` 입니다. 학교·공용 와이파이는 터널 포트가 막힌 경우가 많아 **휴대폰 핫스팟으로 PC 를 연결**하면 대부분 해결됩니다.)
- 시작 직후 **자가 점검 + 원인 진단**이 자동 출력되고, 도중에 터널이 죽으면 `[경고]` 가 바로 표시됩니다.
- 직접 진단: `python netcheck.py https://xxxx.trycloudflare.com` (서버 PC 와 접속 안 되는 PC 양쪽에서 실행해 비교)
- 이 서버는 **외부 유료/무료 API 를 쓰지 않습니다.** Cloudflare 빠른 터널에는 사용량 한도가 없고(동시 200건·SSE 미지원·가동 보장 없음만 제한), 주소가 매번 바뀌는 것이 가장 큰 불편입니다.

### 주소가 바뀌지 않게 하려면 (무료): Tailscale Funnel

터널이 자주 끊기거나 주소가 바뀌는 게 불편하면 고정 주소(`https://내PC.tailnet이름.ts.net`)를 쓸 수 있습니다. 참가자는 Tailscale 을 설치하지 않아도 됩니다.

1. PC 에 Tailscale 설치·로그인 (개인 무료 플랜)
2. 처음 한 번, 명령 프롬프트에서 `tailscale funnel 5000` 실행 → 안내되는 링크에서 Funnel 사용을 승인
3. 서버 실행: `python app.py --public-url https://내PC.tailnet이름.ts.net --trust-proxy --backup-dir "..."`

(Funnel 은 443/8443/10000 포트만 쓸 수 있으며, 같은 PC 에서 `tailscale funnel 5000` 을 켜 둔 상태여야 합니다.)

## 보안 설계

선수 신상 정보(이름·배틀태그·포지션·영웅·Elo·소개·이미지)가 들어가므로 다음을 적용했습니다.

**접근 통제**
- 회원가입 없이 **추측 불가능한 토큰 링크**(192비트)로 역할(주최자/팀장/관전자)을 구분합니다.
- 토큰은 URL `#fragment`로만 전달되어 **서버 로그·프록시·Referer에 남지 않습니다.** 서버에는 SHA-256 해시만 저장합니다.
- 팀장이 어느 팀인지는 서버가 토큰으로 정합니다. 클라이언트가 보낸 팀 번호는 무시합니다.
- 링크가 유출되면 주최자가 **재발급**합니다. 이전 링크는 즉시 무효가 되고 접속 중이던 사람은 끊깁니다.
- 방 생성에는 서버를 연 사람만 아는 **관리자 키**가 필요합니다.

**개인정보 노출 최소화**
- 경매 시작 전에는 등록 인원수만 공개합니다. 진행 중에는 *현재 경매 중인* 선수의 상세 정보만 팀장/관전자에게 보입니다.
- `BLIND`에서는 대기 중 선수의 이름도 보내지 않습니다. 전체 선수 목록은 주최자에게만 전송됩니다.
- 역할별 공개 범위는 `server/views.py` 한 곳에서만 결정됩니다.
- 데이터 폴더(방·선수 명부·이미지)는 **git에 올라가지 않으며**(`.gitignore`), 폴더 0700·파일 0600으로 저장합니다. 방은 보존 기간(기본 14일)이 지나면 자동 삭제되고 주최자가 즉시 삭제할 수도 있습니다. 선수 명부는 요청에 따라 영구 보관이며 주최자가 직접 지울 때만 삭제됩니다.

**웹 공격 방어**
- XSS: 화면 코드가 `innerHTML`을 쓰지 않고 `textContent`만 사용합니다. CSP(`script-src 'self'`, 인라인 스크립트/스타일 금지)도 적용했습니다.
- 외부 사이트에서의 웹소켓 접속(CSWSH)은 같은 출처(Origin)만 허용합니다. 방 생성 API도 Origin을 확인합니다.
- 입력 검증: 타입·길이·범위를 엄격히 확인하고(불리언·문자열 숫자 거부), 제어문자와 방향 전환 문자를 제거합니다.
- 입찰·채팅·주최자 조작에 레이트리밋, 접속/관리자 키 실패에 IP별 잠금이 있습니다.
- 응답에 보안 헤더(CSP, `nosniff`, `X-Frame-Options`, `no-referrer`, `no-store` 등)를 붙이고 서버 버전 정보를 숨깁니다.
- 입찰은 매물 일련번호(`lot_seq`)를 함께 보내야 하며, 마감 직후 도착한 입찰은 서버가 거부합니다.

**한계와 주의 (꼭 읽어주세요)**
- 기본은 **HTTP(암호화 없음)** 입니다. `--lan`은 믿을 수 있는 네트워크(집/팀 공유기)에서만 쓰세요. 인터넷에 포트를 직접 열지 말고, 필요하면 HTTPS 터널을 쓰세요.
- 링크를 가진 사람은 누구나 그 역할로 접속할 수 있습니다. 링크는 해당자에게만 따로 전달하세요.
- 같은 링크로 여러 명이 동시에 접속할 수 있습니다. (한 링크 = 한 사람 원칙은 운영으로 지켜야 합니다.)
- 저장 파일은 **암호화되어 있지 않습니다.** 파일 권한으로만 보호되므로 PC 계정과 디스크 보안에 의존합니다. (Windows는 POSIX 권한 모델이 달라 효과가 제한적입니다.)
- 내장 개발 서버(Werkzeug)를 사용합니다. 소규모 개인 PC 용도에는 충분하지만 대규모 공개 서비스용이 아닙니다.
- 서버를 끄면 경매가 멈춥니다. (다시 켜면 일시정지 상태로 복구되고 주최자가 `재개`하면 이어집니다.)

## 작업지시서 의사코드 대비 수정한 점

작업지시서(TB-ARCH-C-2026)의 C 의사코드를 기반으로 하되, 그대로 옮기면 문제가 되는 부분을 고쳤습니다.

1. **대진 정렬**: `qsort(room->teams)`로 팀 배열 자체를 정렬하면 이후 `teams[team_id]` 접근이 깨집니다. → 팀 배열은 두고 별도 순서 목록을 만듭니다.
2. **재경매 무한 반복**: 재경매에서 또 유찰된 선수를 다시 유찰 큐에 넣으면 끝나지 않습니다. → 별도로 모아 라운드 종료 후 자동 배정합니다.
3. **이전 매물 입찰 혼입**: 매물이 바뀌는 순간 도착한 입찰이 새 매물에 적용될 수 있습니다. → `lot_seq` 불일치 시 거부합니다.
4. **마감 경계**: 틱 직전에 도착한 입찰이 마감 후에 통과할 수 있습니다. → 입찰 전에 항상 만료를 먼저 정리하고, 마감 시각 이후 입찰은 거부합니다.
5. **비율 입찰 버림**: `int()` 버림은 "N% 이상" 조건을 어길 수 있습니다. → 올림을 사용합니다.
6. **재시작 복구**: 서버 시계 기준 마감 시각은 재시작 후 의미가 없습니다. → 남은 시간만 저장하고 일시정지로 복구합니다.
